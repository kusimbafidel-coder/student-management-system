Student Management System

Database design · XAMPP and MySQL

Project scope

This database stores student details, courses, attendance, and exam results. Staff can add, view, and delete records through the website.

COURSES 1 ─── many EXAM_RESULTS

Attendance refers to a student. An exam result refers to a student and a course. The website looks up names from these tables instead of storing duplicate copies.

Database tables and columns

Students

  • student_id — INT, primary key, auto-increment.
  • student_name — VARCHAR(100), required.
  • email — VARCHAR(100), required and unique.
  • enrollment_date — DATE, required.

Courses

  • course_id — INT, primary key, auto-increment.
  • course_code — VARCHAR(20), required and unique.
  • course_name — VARCHAR(100), required.

Attendance

  • attendance_id — INT, primary key, auto-increment.
  • student_id — INT, foreign key to Students.
  • attendance_date — DATE; one record per student per day.
  • status — ENUM: Present or Absent.

ExamResults

  • exam_result_id — INT, primary key, auto-increment.
  • student_id — INT, foreign key to Students.
  • course_id — INT, foreign key to Courses.
  • exam_date — DATE, required.
  • grade — VARCHAR(5), required.
  • marks — DECIMAL(5,2), required, from 0 to 100.

DATABASE RULES AND APP

Keys, relationships & operations

Database rules

  • Each table has its own auto-incrementing primary key.
  • Student email and course code must be unique.
  • Each student can have one attendance record per day; status is Present or Absent.
  • Exam marks must be between 0 and 100.
  • Attendance links to a student. Exam results link to a student and a course.
  • Deleting a student removes their attendance and results. Deleting a course removes its results.
